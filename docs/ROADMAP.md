# 后续规划

当前状态：架构分层、数据源适配、指标计算、LLM 研判、告警、准确率回测已全部打通并实测可用。
下面按「真实使用后多久会痛」排序，而不是按技术难度。

---

## 第一优先：补齐与原始需求的落差

### 1. 告警服务端化（当前最大落差）

**问题**：告警规则目前在浏览器端求值，**关掉页面就停止监控**。
而「实时监控」是这个项目最初的核心诉求之一，现在只做到了「页面开着时监控」。

**方案**：`lib/alerts/engine.ts` 的 `evaluateRules` 是纯函数（输入行情+技术面，输出事件），
当初就是为此设计的，可原样复用。需要补的是：

- 一个常驻轮询进程（Node 定时任务或 `node-cron`），按各规则的 interval 拉数据求值
- 规则从 localStorage 迁到服务端存储（复用 `lib/history/store.ts` 的文件存储模式）
- 通知出口：Telegram Bot 最省事（免费、国内可达、手机推送），或邮件、Bark

**注意**：这会让项目从「打开即用的看板」变成「需要常驻运行的服务」，
部署方式和心智负担都会变。建议做成可选模块，不影响纯看板用法。

### 2. 研判结果缓存与成本控制 ✅ 已完成

按 (距上次研判时长 + 价格漂移 / 上次 ATR%) 判定是否复用。
默认 30 分钟内且漂移小于 0.5×ATR% 即复用，阈值夹在 0.3%~3% 之间。

两个实现要点：
- 缓存判定在拉 K 线**之前**完成，命中时把 3 次 K 线请求和 1 次 LLM 调用一并省掉。
  波动率基准直接取上次研判记录的 ATR%，无需重算。
- 命中缓存**不写新历史记录**——同一次研判若被计入准确率两次会污染回测数据。

实测：命中缓存 0.4-3 秒返回，未命中 37-47 秒。边界逻辑有 14 个用例覆盖
（`npx tsx scripts/test-cache.mjs`）。策略可经环境变量调整，界面提供强制重算入口。

### 3. 研判过程的等待体验

**问题**：实测单次研判 23 秒（中转站 claude-opus-5）到 95 秒（deepseek-v4-pro），
期间界面只有一个「研判中…」，用户不知道是在正常工作还是卡死了。

**方案**：改用流式输出（OpenAI SDK 支持 `stream: true`），
先把 headline 和 direction 推出来，其余字段陆续填充。
注意流式与 JSON 校验的配合——需要等完整 JSON 到齐才能校验，
所以更实际的做法可能是分两次调用，或先显示阶段性进度文案。

### 4. 移动端布局

**问题**：当前是桌面三栏（自选 / 主图 / 分析），手机上完全不可用。
但盯盘场景有相当比例发生在手机上。

**方案**：不是简单加响应式断点就够，需要重新设计信息层级——
手机上应该是「自选列表 → 点进单币详情」的两级结构，而不是三栏压缩。

## 第二优先：让结论更值得信

### 5. 用历史校准修正显示的置信度

准确率面板已经能算出「模型自称 75 分时实际只对 50%」这类校准偏差。
下一步是**把这个偏差用起来**：在研判结果旁显示「历史校准后约 X%」。

这是整个项目里性价比最高的一步——不需要改模型、不需要加数据，
只需要让已有的两个模块互相知道对方的存在。前提是积累足够样本（建议 30 条以上）。

### 6. 多周期共振评分

目前多周期数据直接丢给 LLM 判断是否共振。
可以先用规则算出一个共振强度分（各周期 bias 的加权一致性），
既能稳定输出，也能作为 LLM 判断的对照——两者分歧时本身就是信号。

### 7. 用回测校准规则引擎权重

`lib/indicators/summary.ts` 里的加权打分，权重目前是**凭经验拍的**
（均线排列 2 分、MACD 金叉 1.5 分……）。这些数字没有任何数据支撑。

有了准确率回测框架后，可以让规则引擎也跑历史回测，
用真实数据校准权重。做完这一步，规则引擎才真正配得上作为 LLM 的「对照基线」。

### 8. 技术形态识别

头肩顶、双底、三角形整理、旗形等经典形态的程序化识别。
识别结果同时用于图表标注和喂给 LLM。

## 第三优先：数据维度扩展

### 9. 多币种对比与板块轮动

把自选币的涨跌幅、相对强弱放在一张图上，判断资金往哪流。
这个功能不依赖任何新数据源，现有 API 就够，性价比较高。

### 10. 图表叠加研判结果

把 LLM 给出的支撑/阻力/失效价直接画成水平线。
`PriceChart` 已支持 overlays，改动量小。

### 11. 链上数据

交易所净流入流出、巨鲸地址动向、稳定币供应量变化。

**先决条件**：必须先评估数据源在当前网络下的可达性
（用 `npm run netcheck:proxy` 逐个测）。
Glassnode / CryptoQuant 多数功能需付费，免费额度能拿到的指标有限。

## 待评估 / 明确不做

### 账户接入（读持仓与盈亏）

需要非美国出口的 VPS 代理，架构路径已写在 `docs/DATA-SOURCES.md` 末节。
建议只授予只读权限。**这一步涉及资金安全，不要为了方便而开交易权限。**

### 机器学习价格预测

坦率说：加密市场的短期价格预测很难稳定超过随机基线。

如果要做，**必须先让准确率回测积累足够数据**——
有了 LLM 研判和规则引擎的真实命中率作为基线，
才谈得上评估一个 ML 模型是否真的带来增量。
否则只是又多了一个无法证伪的黑箱。

### 明确不做

- **自动交易 / 跟单** —— 超出「分析看板」定位，资金风险量级完全不同
- **多用户 / 账户体系** —— 个人工具，加数据库和登录只增加维护负担

---

## 一个贯穿始终的建议

**先用起来，让准确率数据自己长出来。**

现在最有价值的动作不是加功能，而是**每天对你实际关注的币点几次研判**。
两三周后准确率面板会给出真实的命中率和校准曲线，
那时你才能回答一个根本问题：这套研判到底值不值得信、该信到什么程度。

在此之前加的任何「提升预测能力」的功能，都无法验证是否真的有提升。
