# 后续规划

当前版本是**项目框架**：架构分层、数据源适配、指标计算、LLM 研判链路已经打通并可运行，
但每一层都还有明显可以做深的地方。下面按建议优先级排列。

## 已完成

- [x] **价格与指标告警** —— 支持价格突破/跌破、RSI 极值、MACD 交叉、
      布林带挤压结束、放量六类规则，浏览器桌面通知，带 15 分钟冷却。
      规则求值是纯函数（`lib/alerts/engine.ts`），将来要搬到服务端做 7×24 告警可原样复用。
- [x] **研判历史留存与准确率回测** —— 每次研判连同当时价格与 ATR 基准落盘，
      到达其声明的时间尺度后自动拉取真实行情检验。
      判定阈值由标的自身 ATR 推导而非固定百分比，避免高波动币种被判定为"总是对"。
      面板强制并列显示无脑基线与置信度校准表。

## 近期
- [ ] **多币种对比视图** —— 把自选币种的涨跌幅、相对强弱放在一张图上，
      判断资金在往哪个板块流
- [ ] **图表叠加研判结果** —— 把 LLM 给出的支撑/阻力/失效价直接画成水平线
- [ ] **研判历史留存** —— 存下每次研判及当时价格，
      过一段时间就能回头检验模型判断的实际准确率（这比任何宣传都更能说明它值不值得信）

## 中期

- [ ] **技术形态识别** —— 头肩顶、双底、三角形整理、旗形等经典形态的程序化识别
- [ ] **多周期共振评分** —— 目前多周期数据交给 LLM 判断，
      可以先用规则算出一个共振强度分，让结论更稳定
- [ ] **链上数据** —— 交易所净流入流出、巨鲸地址动向、稳定币供应量变化。
      注意评估数据源在美国 IP 下的可达性（Glassnode / CryptoQuant 多需付费）
- [ ] **回测框架** —— 让 `summary.ts` 里那套加权打分能跑历史回测，
      用真实数据校准权重，而不是拍脑袋定
- [ ] **成本控制** —— 研判结果按 (币种 + 周期 + 价格变动阈值) 缓存，
      价格没怎么动时直接复用上次结论

## 长期 / 待评估

- [ ] **账户接入（读持仓与盈亏）** —— 需要非美国出口的 VPS 代理，
      架构路径已写在 DATA-SOURCES.md。建议只授予只读权限。
- [ ] **机器学习价格预测** —— 坦率说，加密市场的短期价格预测很难稳定超过随机基线。
      如果要做，建议先把上面的「研判历史留存」做出来，
      有了真实的准确率基线，才谈得上评估模型是否真的带来增量。
- [ ] **移动端适配** —— 当前布局为桌面三栏，手机上需要重新设计信息层级

## 明确不做

- **自动交易 / 跟单** —— 超出"分析看板"的定位，且资金风险量级完全不同
- **多用户 / 账户体系** —— 这是个人工具，加数据库和登录只会增加维护负担
