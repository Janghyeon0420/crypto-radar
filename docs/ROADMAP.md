当前状态：架构分层、数据源适配、指标计算、LLM 研判、告警、准确率回测已全部打通并实测可用。
下面按「真实使用后多久会痛」排序，而不是按技术难度。

## 第一优先：补齐与原始需求的落差

### 1. 告警服务端化 ✅ 已完成

求值已全部移到服务端（`lib/alerts/worker.ts`），只要服务在跑，
无论浏览器是否打开都会持续监控并推送通知。

通知通道可插拔，目前支持企业微信 / 钉钉 / 飞书群机器人（填一条 webhook URL
即可，厂商按域名自动识别）与 Telegram，可同时启用多个。
同一轮触发的多条会合并成一条消息发出。

实现要点：
- `evaluateRules` 纯函数原样复用，worker 只负责调度、取数、持久化与通知
- 规则从 localStorage 迁到 `data/alert-rules.json`，并对旧规则做一次性自动迁移——
  否则用户之前建的规则会静默失效，那比没有这个功能更糟
- **移除了浏览器端求值**。两边同时求值会重复触发、通知发两遍；
  现在浏览器只订阅服务端事件并对新事件弹桌面通知
- 按 币种+周期 分组取数，同组共用一次 K 线请求；无启用规则时一个请求都不发
- worker 状态挂在 `globalThis` 上。Next.js 把 instrumentation 与 API 路由编译进
  不同模块图，模块级变量是两份独立副本，会导致界面误报「未运行」

**常驻部署已补齐**（见 `docs/DEPLOY.md`）：macOS 用 launchd 一条命令装好，
开机自启、崩溃自动拉起；Linux VPS 用 `ecosystem.config.cjs` 走 pm2。
worker 带单实例锁，避免常驻服务与手动 `npm run dev` 同时求值导致通知发两遍。

**仍然存在的限制**：Mac 休眠时进程冻结，合盖即停摆，醒来也不补跑。
真正的 7×24 只能靠 VPS，或让机器不休眠。

### 2. 研判结果缓存与成本控制 ✅ 已完成

按 (距上次研判时长 + 价格漂移 / 上次 ATR%) 判定是否复用。
默认 30 分钟内且漂移小于 0.5×ATR% 即复用，阈值夹在 0.3%~3% 之间。

两个实现要点：
- 缓存判定在拉 K 线**之前**完成，命中时把 3 次 K 线请求和 1 次 LLM 调用一并省掉。
  波动率基准直接取上次研判记录的 ATR%，无需重算。
- 命中缓存**不写新历史记录**——同一次研判若被计入准确率两次会污染回测数据。

实测：命中缓存 0.4-3 秒返回，未命中 37-47 秒。边界逻辑有 14 个用例覆盖
（`npm test`）。策略可经环境变量调整，界面提供强制重算入口。

### 3. 研判过程的等待体验 ✅ 已完成

`/api/analysis` 改为返回 **NDJSON 流**，逐行推送真实阶段：
`quote`（取行情判缓存）→ `klines`（三周期指标）→ `context`（衍生品/情绪/资讯/宏观）
→ `model`（已提交模型）→ `done`。界面显示当前阶段、已等待秒数与四段进度点。

没有走「流式输出模型 token」那条路：研判结果必须完整到齐才能过 Zod 校验，
半个 JSON 驱动不了 UI。真正有用的是**走到哪一步了**——那个信息服务端一直都有，
只是以前没往外说。

存档新增 `durationMs`，模型阶段会一并告知「最近几次约 N 秒」。
「通常 23-95 秒」这种范围宽到等于没说，而「上次 47 秒」是这台机器、
这个供应商的真实数据。进度点全部由服务端事件驱动，不按时间猜——
猜出来的进度条在慢的时候会停在 90% 不动，比一个转圈更让人不安。

### 4. 移动端布局

**问题**：当前是桌面三栏（自选 / 主图 / 分析），手机上完全不可用。
但盯盘场景有相当比例发生在手机上。

**方案**：不是简单加响应式断点就够，需要重新设计信息层级——
手机上应该是「自选列表 → 点进单币详情」的两级结构，而不是三栏压缩。

## 第二优先：让结论更值得信

### 5. 用历史校准修正显示的置信度 ✅ 已完成

研判结论的置信度下方会显示「历史校准后约 X%（±N） · 基于 M 条同区间样本」。
实现在 `lib/history/calibrate.ts`，用 Beta 后验：先验中心取模型自称的分数，
用同区间历史命中情况更新；同区间不足 3 条时退回全部样本。

关键不在算法而在**证据不足时的表现**：少于 10 条已评估记录一律不出数字，
只说还差几条。用 2 条样本算出的「校准后 0%」看起来和 200 条算出的一样权威，
而这个数字的用途恰恰是判断「这条结论该信几分」——宁可不说，不能误导。

**当前状态**：11 条存档、2 条已评估，界面上显示的正是「还需 8 条」。
这个功能要到样本攒够才会真正开始工作，而那取决于使用频率，不取决于代码。

### 6. 多周期共振评分 ✅ 已完成

`lib/indicators/resonance.ts` 按周期长度加权算出共振分与一致性，
在技术面标签页顶部显示（`1h 多 · 4h 多 · 1d 中 · 一致性 100%`），
同时作为确定性输入喂给 LLM，并要求它在与规则判断分歧时明确指出。

**上线前先量了一遍**（`npm run backtest:resonance`，8 币种 7328 个观测）：

| 判定 | 命中率 | 基线 | 信息量 |
|---|---|---|---|
| 共振看多 | 36.5% | 27.4% | +9.2pt |
| 周期背离（按「走成震荡」算命中） | 54.4% | 50.7% | +3.8pt |
| 共振看空 | 17.2% | 21.9% | -4.8pt |

但这批样本的实际走势本底是「涨 27.4% / 跌 21.9%」，**区间单边偏涨 5.5pt**——
在这种样本里看多类判定天然显得准、看空类天然显得差，
所以那个 +9.2pt 多半是行情本身的功劳，不是信号的。相对可信的只有
「背离时更容易走成震荡」这条不依赖方向的结论，而它也只有 +4.5pt。
加上观测窗口高度重叠（有效独立样本约 305 条），几个百分点很可能就是噪音。

**因此定位为「各周期状态是否一致」的描述，不承担预测职责**，界面与 prompt 都如实标注。

### 7. 用回测校准规则引擎权重 ✅ 已完成（结论是不改）

`lib/indicators/backtest.ts` + `npm run backtest`。规则引擎是确定性的，
不必等样本——直接在历史 K 线上逐根重放，22216 个观测，按时间 7:3 切分。

结论与预期相反：**除 RSI 极值外，趋势类信号在样本上略微反向**
（均线排列 -3.3pt、MA200 -2.2pt、MACD 金叉/死叉 -1.9pt），
规则引擎整体命中率 30.2%，而「无脑全猜震荡」有 51.9%。

按实测推出的权重会把 5.16/6.0 全压在 RSI 极值上，表态比例从 79% 掉到 7.4%，
整体命中率看似升到 51.1%——但那是沉默换来的，不是预测力换来的，且仍低于基线。
所以**保留原权重**，改的是定位：bias 从「方向判断」降级为「技术面状态的透明摘要」。

`--apply` 写回的闸门因此有两道：既要在测试集上有提升，又要真的跑赢基线。

这一项原本的目标是「让规则引擎配得上作为 LLM 的对照基线」。
测完的答案是：**它现在不配**，而这个答案本身比调出一组好看的权重有价值得多。

### 8. 技术形态识别 —— 暂不做

头肩顶、双底、三角形整理等经典形态的程序化识别。

**决定先不做**，理由是已有的三次回测：规则引擎权重（无信息量）、
多周期共振（方向类结论是牛市样本的假象）、主动成交流（噪音）——
技术面派生指标至今没有一个测出边际信息量，而形态识别属于同一类。

要做的话，先假设它没用，再让数据推翻这个假设：
识别逻辑写完后必须先跑回测，测出边际信息量再决定是否进入 UI 与 prompt。

### 数据源框架重建 ✅ 已完成（2026-08-21）

接入 FRED/ALFRED、Finlight 与 Binance WS 三家，按「行情 / 数值 / 文本」三层重新分工，

- **鹰鸽判断** —— 基于 FOMC 声明**原文**的词典打分 + 投票分歧，附逐条依据与对加密的传导。
  已回测 41 次会议：鹰派之后从未降息、鸽派之后从未加息、中性之后 100% 按兵不动

「买卖压力」「大单流向」，是目前完全没有的微观结构维度。见下方第 12 项。

### 宏观（美联储）✅ 已完成

接入三类免费无 Key 的美联储数据：政策利率（纽约联储 EFFR 接口，含目标区间）、
下次议息倒计时（FOMC 日历）、官方资讯（货币政策新闻稿 / 官员讲话 / 国会证词 RSS）。
利率与倒计时常驻图表下方的环境条，完整内容在「宏观」标签页，
并作为流动性背景一并喂给 AI 研判。

实测全部从中国大陆直连可达（0.8-1.8s），与 OKX 恰好相反，见 `docs/DATA-SOURCES.md`。

两个实现要点：
- **宏观资讯与行业资讯分开**，不合并进同一个列表。两者更新频率差两个数量级，
  混排的结果是几周一条的美联储讲话被每小时几十条的行业资讯永久挤到列表末尾。
- **议息日历只能抓 HTML**（官方无结构化接口），解析失败时显示「日历不可用」，
  不做硬编码兜底——过期的议息日程比没有日程更危险。
  `npm run test:live` 会拉真实页面校验解析。

**还可以再往下做**：CME FedWatch 的降息概率是市场对议息结果的定价，
比「利率是多少」更有信息量，但没有免费接口；CPI / 非农等数据发布日历同理，
需要评估数据源（BLS 有 API 但需注册 key）。

### 9. 多币种对比与板块轮动 ✅ 已完成

新增「对比」标签页与 `/api/market/compare`。一次 1h K 线请求（200 根）
同时算出 1h / 24h / 7d 三个窗口，不必为每个窗口各拉一次。

核心不是「谁涨了多少」，而是**相对 BTC 的超额收益**：
加密高度同涨同跌，「涨了 5%」本身说明不了什么——同一天 BTC 涨 6% 的话，
这个 5% 其实是跑输的。自选里没有 BTC 时如实显示「无法计算相对强弱」，
不拿别的币凑一个基准。

这是描述而非预测：它说的是资金**过去**流向了哪里。

### 10. 图表叠加研判结果 ✅ 已完成

`PriceChart` 新增 `priceLines`（水平价位线，与 `overlays` 的逐根序列分开——
用序列画水平线会随时间轴平移被裁切）。Dashboard 自动取该币最近一次研判的
支撑 / 阻力 / 失效价画上去，工具栏有「研判价位」开关。

失效价用实线且颜色最醒目：支撑阻力是「可能反应的位置」，
失效价是「到这里说明整个判断已不成立」——性质不同，画成一样粗细
会让最该注意的那条淹没在其余几条里。

数据走历史接口（带 `evaluate=0`，只读不触发评估），
所以不必打开研判面板、也不产生任何调用费用。

### 12. Binance WebSocket 微观结构 ✅ 已完成

`lib/ws/microstructure.ts` + 技术面标签页的「盘口 · 近 60 秒」：
价差、盘口失衡、主动买入占比，只订阅当前币种，更新节流 500ms。

**上线前先量了**（`npm run backtest:flow`）。K 线第 9 个字段就是主动买入量，
所以这个指标有历史可测。5m/15m/1h × 1~12 根共 11 组组合，
最好的一组（5m/1 根）信息量只有 +1.5pt 且随跨度单调衰减——噪音的形状，
而且是 11 组里挑出来的最好看的那个。

测之前特意换了尺子：默认阈值把有效波动钳在 1% 下限，那是为数日研判设计的，
5 分钟线看 3 根要求 1% 波动等于一切都是震荡。改用按 √跨度 缩放的口径后
仍然测不出方向性，这个结论才算数。

所以它的定位是**状态描述**：价差是否突然变宽、这波成交是谁在主动。
`taker_flow` 在权重表里是 0，界面上不配进度条也不用涨跌配色。

### 11. 链上数据 ✅ 已完成

按本项目一贯的前提**先实测可达性与免费额度**（2026-08-21，出口美国）：

| 源 | 结果 |
|---|---|
| DefiLlama 稳定币 | ✅ 免费无 key，历史可回溯到 2017-11（3188 天） |
| Blockchair BTC 统计 | ✅ 免费无 key，一次请求 37 个字段 |
| blockchain.info 图表 | ✅ 可用（未采用，Blockchair 已覆盖） |
| mempool.space | ❌ 两次尝试均超时，判定不可用 |
| Glassnode / CryptoQuant | 多数指标付费，未接入 |

接了两类，挑选标准是**传导路径清楚**而不是「链上能查到什么就放什么」：

- **稳定币总供应**——链上可随时买币的钱，与美联储净流动性构成
  「场内水位 / 宏观水位」一对。两者背离时值得注意：宏观在收紧而稳定币仍增发，
  说明有资金逆着大环境进场。
- **BTC 网络状态**——算力、待确认笔数、建议费率、市占。拥堵与安全边际的描述。

**上线前照例先量了**（`npm run backtest:stablecoin`）。「稳定币增发 = 买盘燃料」
这个说法流传很广，但用 1000 天日线 × 回看 7/30 天 × 前瞻 7/14/30 天共 6 种组合测下来，
**扩张组与收缩组的后续涨跌差异全部小于 3pt**。所以界面与 prompt 里都明确标注
「已回测、无预测力，仅作水位参考」——不这么写的话，模型很容易把它当看涨依据。

这是第四次回测得出「无信息量」的结论（前三次：规则引擎权重、多周期共振方向、
主动成交流）。至今唯一测出真实分离度的是鹰鸽词典。

## 工程与运维

功能之外的事。它们不改变看板能做什么，但决定它能不能被信任、能不能一直跑着。

### E1. 到期评估只在打开页面时触发 ✅ 已完成

常驻 worker 每 15 分钟调用一次 `evaluateDueRecords()`——不打开看板，
研判也会被按时检验。这直接解开了置信度校准的卡点（要 10 条已评估才出数）。

读取→评估→有变更才写盘这套逻辑抽成了共享函数，路由与 worker 共用。
两边各写一遍「有没有变化」的判断迟早会漂移，而那种漂移的表现是
「有时候评估了有时候没有」，极难查。

低频任务自己记上次执行时间，与轮询间隔解耦——
把 `ALERTS_POLL_SECONDS` 调成 20 秒也不会因此每 20 秒评估一次。

### D1. 付费接口没有访问控制

`next start` 监听 `*:3000`（全部网卡），而 `/api/analysis` 没有任何
auth / token / 限流。同一个 wifi 下任何人 POST 一下就能烧 API 额度，
一次 $0.02-0.05，循环调用就是持续扣费。

以前只在开发时开着还好，常驻之后笔记本会连咖啡馆、酒店、机场的网络。
最小修法是让它只听本机（`next start -H 127.0.0.1`）；
真要在手机上看盘才需要上 token。

### D2. 服务自身没有监控 ✅ 已完成

复用现成的通知通道（`dispatchText`）：

- **启动时**发一条上线通知。两个作用：确认通道确实通（配错了当场就知道，
  而不是等第一次真实触发才发现），以及常驻服务意外重启时留下痕迹
- **连续 3 轮失败**发一条中断告警，**恢复时**再发一条

只在跨过阈值的那一轮发一次。每轮都发会在网络断开的整个期间刷屏，
那和不发一样糟。未配置通知通道时全部静默——只记日志。

### D3. `data/` 没有备份 ✅ 已完成

常驻 worker 每天打一份快照，保留最近 14 份；也可手动 `npm run backup`。
目录名用日期而非时间戳，所以重复调用是幂等的，不会堆出上千个目录。

⚠️ **默认的 `data/backups` 与源文件在同一块盘上**。这只防误删和写坏，
防不住硬盘故障或机器丢失。要防那个，把 `DATA_BACKUP_DIR` 指到外接盘或同步盘。
脚本会在用默认路径时主动提醒这一点——**以为自己有备份而其实没有，
比明知没有更危险**。

### E2. `analyses.json` 全量读写

11 条记录已经 58KB（每条约 5KB），每次研判和每次打开历史都要全文解析。
一年约 18MB。不紧急，但迟早要分片或归档。

### F1. 没有 CI ✅ 已完成

`.github/workflows/ci.yml`：每次 push 与 PR 跑类型检查、lint、离线测试、生产构建。
四步都用 `if: always()`，一步失败仍跑完剩下的——排查时
「只有类型错」和「类型和测试都错」是两种不同的情况。

联网测试（`npm run test:live`）单独一个 job 且 `continue-on-error`：
它依赖美联储官网的页面结构，上游改版会让它失败——
那是需要知道的真实信息，但不该拦住代码合并。

已在不含 `.env.local` 的干净副本上验证过四步全过，
确认 CI 环境无密钥也能跑通。

## 待评估 / 明确不做

### 账户接入（读持仓与盈亏）

需要非美国出口的 VPS 代理，架构路径已写在 `docs/DATA-SOURCES.md` 末节。
建议只授予只读权限。**这一步涉及资金安全，不要为了方便而开交易权限。**

### 机器学习价格预测

坦率说：加密市场的短期价格预测很难稳定超过随机基线。

如果要做，**必须先让准确率回测积累足够数据**——
有了 LLM 研判和规则引擎的真实命中率作为基线，
才谈得上评估一个 ML 模型是否真的带来增量。
否则只是又多了一个无法证伪的黑箱。

### 明确不做

- **自动交易 / 跟单** —— 超出「分析看板」定位，资金风险量级完全不同
- **多用户 / 账户体系** —— 个人工具，加数据库和登录只增加维护负担

---

## 一个贯穿始终的建议

**先用起来，让准确率数据自己长出来。**

现在最有价值的动作不是加功能，而是**每天对你实际关注的币点几次研判**。
两三周后准确率面板会给出真实的命中率和校准曲线，
那时你才能回答一个根本问题：这套研判到底值不值得信、该信到什么程度。

在此之前加的任何「提升预测能力」的功能，都无法验证是否真的有提升。
