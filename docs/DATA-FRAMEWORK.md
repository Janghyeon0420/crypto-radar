# 数据源框架

这份文档回答一个问题：**每一类判断，应该由哪个源负责？**

不是「我们接了哪些 API」的清单——那个 `DATA-SOURCES.md` 里有。
这里讲的是分工：为什么某个数字必须来自这个源而不是那个源，
以及两个源给出不同答案时以谁为准。

---

## 三层

```
第一层  行情    Binance          价格、成交、盘口         秒级 ~ 分钟级
第二层  数值    FRED / ALFRED    利率、流动性、通胀        日 ~ 月级
第三层  文本    美联储官网 + Finlight  政策措辞、市场叙事    事件驱动
```

三层的时间尺度差了好几个数量级，这不是缺陷而是分工：
第一层解释「这几根 K 线在做什么」，第三层解释「为什么整个市场同时转向」，
第二层是把两者连起来的那根线——**流动性**。

## 第一层：行情（Binance）

| 用途 | 端点 | 说明 |
|---|---|---|
| K 线 / 24h 行情 / 交易对 | `data-api.binance.vision` REST | 服务端拉，指标在服务端算 |
| 实时价格 | `data-stream.binance.vision` WS | 浏览器直连，公开数据无需凭据 |

### 为什么不用 `stream.binance.com`

实测（2026-08-21，出口美国洛杉矶）：

| 端点 | 结果 |
|---|---|
| `data-stream.binance.vision` | ✅ 全部现货流可用，含组合流 |
| `stream.binance.com` | ❌ 超时 |
| `fstream.binance.com`（U 本位合约） | ❌ 超时 |

**衍生品数据因此仍走 OKX**，不是偏好问题，是 `fstream` 根本连不上。
镜像支持的现货流已实测可用：`aggTrade` / `bookTicker` / `depth20` /
`kline_*` / `miniTicker` / `ticker`，以及 `/stream?streams=` 组合流。

### 微观结构：唯一的秒级维度

`lib/ws/microstructure.ts` 订阅当前币种的 `bookTicker` + `aggTrade`，
60 秒滚动窗口给出价差、盘口失衡、主动买入占比。其余所有指标都基于 K 线，
最快也是分钟级——这是唯一能回答「此刻正在发生什么」的一层。

只订阅**当前选中的币**：这两个流每次盘口变动、每笔成交都推，
给整个自选列表订阅纯属浪费带宽与电量。推给 React 的更新节流到 500ms，
否则每秒几十条 aggTrade 只会烧 CPU。

**但它不是方向信号，这一点是量过的。** K 线的第 9 个字段就是主动买入量
（`takerBuyVolume`），意味着这个指标有 1000 根历史可回测。
`npm run backtest:flow` 在 5m/15m/1h × 1~12 根跨度共 11 组组合上测：

| 周期 / 跨度 | 触发次数 | 命中率 | 基线 | 信息量 |
|---|---:|---:|---:|---:|
| 5m / 1 根 | 784 | 23.5% | 22.0% | +1.5pt |
| 5m / 3 根 | 782 | 22.9% | 21.5% | +1.4pt |
| 5m / 12 根 | 777 | 22.8% | 23.5% | −0.7pt |
| 1h / 6 根 | 774 | 18.9% | 18.9% | +0.0pt |

最好的一组只有 +1.5pt，且随跨度单调衰减——正是噪音的形状。
而且这是 11 组里挑出来的最好看的一组，多重比较下 +1.5pt 毫无意义。

测这个之前特意换了尺子：默认的「有效波动」阈值把 ATR% 钳在 1%~10%，
那是为数日研判设计的；5 分钟线向前看 3 根要求 1% 波动，等于一切都是震荡。
所以短跨度改用按 √跨度 缩放、不设下限的口径（`shortHorizonThreshold`）。
**换了合适的尺子仍然测不出方向性**，这个结论才算数。

因此界面上它不配进度条、不用涨绿跌红——那套配色会暗示方向，
而这个量并不预示方向。权重表里 `taker_flow` 的权重是 0。

### 不使用 API Key

公共行情与 WebSocket 全部无需凭据。**账户密钥不进这个项目**——
一旦配上就是账户权限，而看板的定位是分析而非交易。

## 第二层：宏观数值（FRED / ALFRED）

`lib/datasources/fred.ts`。免费 key，实测中国大陆直连可达。

取代了原先「只拉一个当前政策利率」的做法。对加密资产而言，
**利率水平本身不如流动性重要**：真正驱动风险资产估值的是市场上有多少钱。

### 核心指标：净流动性

```
净流动性 = 美联储总资产(WALCL) − 隔夜逆回购(RRPONTSYD) − 财政部一般账户(WTREGEN)
```

美联储资产是投放的总量，而逆回购和 TGA 里的钱趴着不动、没进入市场循环。

**两个会静默算错的地方**，两者都不会抛异常：

1. **单位不统一**。WALCL 与 WTREGEN 是「百万美元」，RRPONTSYD 是「十亿美元」。
   直接相减差 1000 倍，得到一个看着像模像样的错数字。
   代码里用 `SERIES[id].scale` 统一换算成十亿美元。
2. **频率不统一**。WALCL/WTREGEN 周频、RRPONTSYD 日频、M2 月频。
   按数组下标对齐等于把不同日期的值相减，必须按日期取「截至该日的最新值」。
   `asOf` 字段把三项各自的实际观测日期一并返回，不假装它们是同一天。

### 其余序列

| 序列 | 用途 |
|---|---|
| `DFF` | 联邦基金有效利率 |
| `DGS10` / `T10Y2Y` | 长端利率与曲线形态 |
| `CPIAUCSL` / `UNRATE` | 决定美联储下一步的两个数据 |
| `DTWEXBGS` | 美元指数，风险资产的反向指标 |
| `M2SL` | 货币供应 |

### 数据发布日历

`/fred/releases/dates` 一次返回三千多条，绝大多数与加密无关。
只保留会引发跨资产重定价的几类：CPI、非农、PCE、GDP、美联储资产负债表。
**这些日子的行情性质与平时不同**，值得提前知道。

### ALFRED：修订历史

同一个数字在不同时点是不一样的——GDP 初值与终值可以差很多。
用修订后的数据去检验当时基于初值做出的判断，等于把未来信息漏给了过去。
`fetchRevisions()` 把初值与现值的差异摆出来，用途是**防止回测作弊**，
不是看新闻。

## 第三层：政策文本与资讯

### 鹰鸽判断只用官方原文

`lib/macro/hawkdove.ts` 的输入是 federalreserve.gov 上的**声明全文**，
不是新闻转述。理由很直接：同一份声明在不同媒体笔下可以是
「美联储态度强硬」也可以是「美联储按兵不动」，而市场逐字读的是原文。

打分方法是**词典 + 投票分歧**，不是 LLM：

- 央行措辞高度程式化、逐词斟酌，正是词典方法最有效的场景
- 确定性、免费、即时；同一份文本永远得到同一个分数，因而**可回测**
- LLM 的解读留在研判环节，那里它能结合行情一起看

输出必然带**逐条证据**（命中哪句话、加减多少分）。不可核对的情绪分
在这里没有价值——用户需要能自己判断这个分数讲不讲理。

#### 投票分歧是信息量最高的一项

一份措辞温和的声明，若有三位委员投票主张加息，其实际鹰派程度远高于字面。
纯词频统计必然漏掉这一层。

解析异议时踩过两个坑，都写进测试了：

1. **异议句会污染词典**。异议句里写着「who preferred to raise the target range」，
   词典把它当成委员会加息——一份「维持利率」的声明被记上加息分，还与异议票重复计分。
   修法：词典只扫 `decisionBody()` 切出的决议正文，异议由 `detectDissent()` 单独处理。
2. **中间名缩写带句点**。用 `[^.]*` 圈定异议名单会在「Michelle W.」处截断，
   于是每份声明都解析成「无异议」而毫无报错。改用「who preferred」作终止符。

#### 已经回测过

`npm run backtest:hawkdove` —— 用历史 FOMC 声明与 FRED 的实际利率路径检验。
41 次会议的结果：

| 本次倾向 | 次数 | 后续加息 | 后续未动 | 后续降息 | 平均变化 |
|---|---:|---:|---:|---:|---:|
| 偏鹰 | 22 | 45.5% | 54.5% | 0.0% | +0.238pt |
| 中性 | 8 | 0.0% | 100.0% | 0.0% | +0.003pt |
| 偏鸽 | 11 | 0.0% | 45.5% | 54.5% | −0.155pt |

**零交叉**：鹰派声明之后从未降息，鸽派之后从未加息。

但要诚实看待：FOMC 一年只开 8 次，样本天生稀少；政策周期本身高度自相关
（加息周期里连续加息），这会让任何「鹰派→加息」的关联显得比实际更强。
所以它的定位是**对官方措辞的结构化摘要**，可以用来理解当前政策基调，
不该当成对下次议息的预测。

### 鹰鸽 → 加密的传导

路径清楚：收紧 → 无风险收益率上升、流动性减少 → 风险资产估值承压，
而加密处在风险资产里久期最长的一端，通常放大这个方向。

但**方向清楚不等于可预测**：传导有时滞、幅度不定，市场还常常提前定价。
所以 `cryptoImpact` 只给方向与理由，**不给概率**——给概率就是在假装
知道自己不知道的事。

### Finlight：广度，不是判断依据

`lib/datasources/finlight.ts`。相比 RSS 的价值在广度与结构化标签：
一次请求覆盖数百家源，自带 categories / countries。

**实测于 2026-08-21：当前免费 key 不返回实体识别与正文**。
请求里带 `includeEntities` / `includeContent` 不报错，但也没有对应字段。
接口形态还有个坑：v2 只接受 POST，GET 一律 404。

这反而让分工更清楚：**判断来自官方原文，广度来自 Finlight**。
若将来升级到付费档拿到实体与情绪，它们也应作为参照而非替代——
媒体情绪与政策措辞是两件事。

### 宏观与行业资讯分开

两者更新频率差两个数量级：加密资讯每小时几十条，美联储讲话几周一条。
混排的结果是宏观信息被永久挤到列表末尾再被 `slice` 截掉，接了等于没接。
所以 `NewsItem.category` 区分 `macro` / `crypto`，接口也是分开的。

## 第四层：链上（DefiLlama + Blockchair）

`lib/datasources/onchain.ts`。同样先实测再选型（2026-08-21，出口美国）：
DefiLlama 与 Blockchair 免费无 key 且可达，**mempool.space 两次尝试均超时**，
Glassnode / CryptoQuant 多数指标付费，均未接入。

只接两类，挑选标准是传导路径清楚：

- **稳定币总供应**（DefiLlama，历史回溯到 2017-11）——链上可随时买币的钱。
  与美联储净流动性构成「场内水位 / 宏观水位」一对，两者背离时最有信息量。
- **BTC 网络状态**（Blockchair）——算力、待确认笔数、建议费率、市占。

**已回测，结论是没有预测力**（`npm run backtest:stablecoin`）：
1000 天日线 × 回看 7/30 天 × 前瞻 7/14/30 天共 6 种组合，
扩张组与收缩组的后续涨跌差异全部小于 3pt。

所以界面与 prompt 都明确写着「已回测、无预测力，仅作水位参考」。
这条标注是必要的——「稳定币增发所以看涨」流传太广，不写清楚的话
模型会自己把它当依据写进结论。

有一处实现细节值得记：变化率按**天数**回看而不是按数组下标往回数 N 个。
上游偶有缺日，数下标会让「7 天变化」实际变成 9 天或 5 天的变化，
而这个错误不报任何异常，只让百分比悄悄失真。`changeOverDays` 有 10 条断言覆盖。

## 冲突时以谁为准

| 情形 | 以谁为准 | 理由 |
|---|---|---|
| 政策利率：FRED vs 纽约联储 | 纽约联储 | 它同时给出目标区间上下沿，FRED 的 DFF 只有实际成交值 |
| 政策态度：官方原文 vs 媒体报道 | **官方原文** | 转述会加入解读；市场交易的是原文 |
| 方向判断：规则引擎 vs LLM | 都不单独采信 | 规则引擎已实测跑不赢基线（见 ARCHITECTURE 决策 6），分歧本身才是信号 |
| 衍生品：Binance vs OKX | OKX | `fstream.binance.com` 实测不可达，不是选择问题 |
| 流动性：净流动性 vs 稳定币供应 | 都看，且看两者是否背离 | 一个是宏观水位一个是场内水位，背离本身才是信息 |

## 降级行为

每一路数据独立 settle，任何一路失败只少一块内容，不会让整个面板空白。
受限网络下这一点尤其重要——**部分可用**必须是常态而不是异常。

| 缺什么 | 后果 |
|---|---|
| 未配 `FRED_API_KEY` | 无净流动性、无宏观数值、无发布日历；利率与议息倒计时仍在 |
| 未配 `FINLIGHT_API_KEY` | 宏观资讯只剩美联储官方 RSS |
| 声明原文抓取失败 | 无鹰鸽判断；最多回溯三场会议后放弃，不拿来路不明的文本打分 |
| FOMC 日历页改版 | 无议息倒计时、无鹰鸽判断（两者都依赖它推算日期），**不做硬编码兜底** |
| DefiLlama / Blockchair 不可用 | 少一块链上内容，其余不受影响 |

密钥全部走环境变量，`.env.local` 已被 `.gitignore` 覆盖。
需要密钥的脚本用 `tsx --env-file=.env.local` 加载。

## 启动预热与缓存归属

冷缓存时一次宏观快照要拉十几个上游，实测通常 2-3 秒，但出现过一次 30 秒以上。
而这份数据支撑着图表下方常驻的利率与议息倒计时——落在用户面前就是半分钟的「—」。

服务常驻之后解法很简单：`instrumentation.ts` 在启动时先拉一遍。
反正数据要拉，不如让等待发生在没有人看的时候。实测预热约 2 秒，
之后首个请求 **11ms**。

但这里有个坑，踩过第二次了：**Next 把 instrumentation 与 API 路由编译进
不同的模块图，模块级变量在两边是各自独立的副本**。
`http.ts` 的缓存原本就是模块级 Map，于是预热拉到的数据路由根本看不见——
预热等于白做，而且告警 worker 与 API 路由一直在各自向上游要同一份数据。

修法与 `alerts/worker.ts` 当初一样：缓存挂 `Symbol.for()` 键的 `globalThis`。
这类问题不会报错，只会表现为「明明缓存了却还是慢」。
